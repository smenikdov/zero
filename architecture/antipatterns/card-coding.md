# Карточное программирование (Card Coding)

## Определение

Карточное программирование (Card Coding) — подход, при котором разработчик механически реализует ровно то, что
написано в задаче/тикете, не вникая в контекст системы, предметную область и архитектурные последствия. Каждая
карточка превращается в изолированный «заказ», а код — в лоскутное одеяло из разрозненных решений.

## Подробности

Термин происходит от практики управления задачами через карточки (Kanban-доски, Jira-тикеты, GitHub Issues).
Сами по себе карточки — полезный инструмент, но антипаттерн возникает, когда разработчик:

- **Не задаёт вопросы**: видит задачу «добавить кнопку экспорта» и делает ровно кнопку, не уточняя формат,
  куда экспортировать, какие поля включать, нужно ли логирование, влияет ли это на производительность.
- **Не смотрит на соседние карточки**: реализует фичу А и фичу Б независимо, даже если они дублируют
  функциональность или конфликтуют.
- **Игнорирует рефакторинг**: карточка не предписывает улучшать код — значит, код остаётся гнить.
- **Копирует соседний код без понимания**: «в соседнем модуле сделано так же, скопирую».

Card Coding часто маскируется под «следование процессу» и «работу по задаче», но по сути это отказ от
инженерного мышления в пользу роли «кодировщика на конвейере».

Отличие от смежных антипаттернов:
- **Cargo Cult** — слепое копирование чужих практик; Card Coding — слепое следование своей же задаче.
- **Copy-Paste-Driven Development** — копирование кода; Card Coding — копирование отсутствия мысли между
  задачами.

## Почему это проблема

- **Фрагментация кодовой базы** — система состоит из кусков, которые не согласованы друг с другом ни по стилю,
  ни по логике.
- **Дублирование** — одна и та же функциональность реализуется в разных местах по-разному.
- **Накопление технического долга** — рефакторинг откладывается бесконечно, потому что «нет карточки на рефакторинг».
- **Хрупкость** — изменение в одной части системы ломает другую, потому что автор не учёл связи.
- **Выгорание команды** — разработчики перестают чувствовать ownership за продукт, превращаясь в исполнителей.

## Как избежать

1. **Понимайте контекст задачи.** Прежде чем писать код, выясните: зачем это нужно? Как это впишется в систему?
   Кто и как будет этим пользоваться?
2. **Думайте на шаг вперёд.** Карточка — это минимальная формулировка, а не исчерпывающая спецификация.
   Предусмотрите очевидные расширения.
3. **Рефакторите смежный код.** Если задача затрагивает грязный модуль, приведите его в порядок — даже если
   в карточке этого нет.
4. **Обсуждайте карточки с командой.** Grooming и планирование — не просто оценка в story points, а возможность
   выявить пересечения и конфликты.
5. **Владейте продуктом, а не задачей.** Переход от «я сделал свою задачу» к «я улучшил продукт» — ключевое
   изменение мышления.

## Пример

```js
// Карточка №42: «Добавить экспорт пользователей в CSV»

// ❌ Card Coding: сделано ровно то, что в карточке
function exportUsers() {
  const users = db.query("SELECT * FROM users");
  const csv = users.map(u => `${u.name},${u.email}`).join("\n");
  fs.writeFileSync("/tmp/export.csv", csv);
}

// Проблемы:
// - Формат жёстко зашит, нет поддержки других форматов
// - Данные не фильтруются, нет пагинации
// - Файл всегда в /tmp, не подходит для продакшена
// - Нет обработки ошибок
// - Не учтено, что пользователей может быть 10 миллионов
// - Соседний модуль orders уже умеет экспортировать — дублирование

// ✅ Осмысленная реализация: учтён контекст системы
class CsvExporter {
  export(data, filename) { /* ... */ }
}

class UserExporter {
  constructor(exportStrategy, logger) {
    this.strategy = exportStrategy;
    this.logger = logger;
  }

  async exportAll(filters = {}) {
    this.logger.info("Starting user export", { filters });
    let offset = 0;
    const batchSize = 1000;

    while (true) {
      const batch = await db.query(
        "SELECT name, email FROM users WHERE ... LIMIT ? OFFSET ?",
        [batchSize, offset]
      );
      if (!batch.length) break;
      await this.strategy.writeBatch(batch);
      offset += batchSize;
    }

    this.logger.info("Export completed");
    return this.strategy.finalize();
  }
}
```
