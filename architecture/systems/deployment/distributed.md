# Распределённые системы (Distributed Systems)

## Определение

Распределённая система — модель развёртывания, при которой приложение состоит из нескольких независимых процессов
(и часто узлов), взаимодействующих по сети. Нет единого адресного пространства: узлы могут отказывать по отдельности,
часы не синхронизированы идеально, а обмен данными идёт через сообщения, а не через прямые вызовы функций в памяти.

## Подробности

Это противоположность монолиту как модели развёртывания: не «один процесс — один деплой», а «несколько процессов —
согласованная работа». Конкретная топология при этом может быть разной: Multitier, Microservices, Serverless и другие.

**Характерные свойства**:
- **Раздельная память** — нет общей кучи; состояние передаётся по сети.
- **Частичные отказы** — один узел может упасть, пока другие продолжают работать.
- **Сетевая неопределённость** — latency, потеря пакетов, дубликаты, таймауты.
- **Согласованность** — сильные ACID-транзакции на всю систему обычно недоступны; часто eventual consistency.

Распределённость — не цель сама по себе, а следствие требований: масштаб, изоляция отказов, независимые релизы,
геораспределение.

## Плюсы

- **Масштабирование** — наращивать можно отдельные части системы.
- **Изоляция отказов** — падение одного процесса не обязано ронять всё.
- **Независимая эволюция** — разные команды и технологии на разных узлах.
- **Гибкость размещения** — ближе к пользователю, в разных ЦОД, в разных облаках.

## Минусы

- **Сложность** — сеть, наблюдаемость, деплой, отладка заметно тяжелее монолита.
- **Согласованность данных** — сложнее гарантии, чем в одной БД.
- **Операционные затраты** — инфраструктура, SRE, платформенные инструменты.
- **Риск distributed monolith** — сеть есть, а независимости деплоев нет.

## Когда применять

- Нагрузка или команда переросли возможности одного процесса/монолита.
- Нужны независимые деплои и масштабирование частей системы.
- Требуются высокая доступность и изоляция отказов.
- Есть готовность платить сложностью за эти свойства.

## Схема

```
        ┌─────────┐   сеть   ┌─────────┐   сеть   ┌─────────┐
        │ Узел A  │ ◄──────► │ Узел B  │ ◄──────► │ Узел C  │
        └─────────┘          └─────────┘          └─────────┘
              │                    │                    │
              └──────── частичные отказы, latency ──────┘
```
